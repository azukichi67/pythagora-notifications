# ドメイン

## 用語

| 用語 | 定義 |
|---|---|
| 放送 | 番組表上の 1 回の放送枠 |
| ピタゴラ系 | 番組名に「ピタゴラ」を含む放送。`ピタゴラスイッチ` `ピタゴラスイッチ ミニ` `大人のピタゴラスイッチ` が該当する |
| 対象期間 | 取得実行日から 8 日分（当日＋7日先）。NHK 番組表 API の情報提供期間の上限 |
| サマリ | 対象期間のピタゴラ系放送を一覧化した、週 1 回送る 1 通のメッセージ |
| 定時放送 | Eテレ平日 6:45-6:55 / 18:40-18:50、総合早朝 4 時台の「ミニ」など、繰り返し放送される枠 |
| 特別版 | 定時放送以外の時間帯に放送される回 |

## データモデル

### 放送

| 属性 | 内容 |
|---|---|
| 番組名 | 番組シリーズの名前。例: `ピタゴラスイッチ` `ピタゴラスイッチ ミニ` |
| サブタイトル | その回の内容。例: `紙コップコップ暗号`。複数ある場合は `▽` で連結されている |
| 開始日時 | 放送開始の日時（JST） |
| 終了日時 | 放送終了の日時（JST） |

## モデル上の決定と根拠

### 定時放送と特別版をシステムは区別しない

用語としては定義するが、判定処理は持たない。番組名に「スペシャル」が含まれる場合もあるが、それはサブタイトル内の語であり、番組名からは特別版かどうかを判別できない。全放送を通知することで判定ロジックそのものを不要にする。

### 番組名とサブタイトルは API の分割済みフィールドをそのまま使う

NHK 番組表 API Ver.3 は、番組名とサブタイトルを連結した `name` とは別に、分割済みの `identifierGroup.tvSeriesName` / `identifierGroup.tvEpisodeName` を持つ。後者を使う。

```
name          : ピタゴラスイッチ　ミニ▽ねんどれナンドレラッツの跡じまん▽うた
tvSeriesName  : ピタゴラスイッチ ミニ
tvEpisodeName : ▽ねんどれナンドレラッツの跡じまん▽うた
```

`name` を `▽` で分割する方法も取れるが、番組名の直後に全角スペースが入る揺れがあり、分割後の正規化が必要になる。`tvSeriesName` は半角スペースに正規化済みのため、その処理自体が不要になる。`tvEpisodeName` の先頭の `▽` を除去するだけでよい。

ニュース・解説・単発番組では `tvSeriesName` が空になるが、ピタゴラ系は 8 日分 × 2 波の実データ 16 件すべてが埋まっており、定時放送・特別版のいずれにも欠けがなかった。フィールドの詳細は [nhk-api.md](./nhk-api.md) を参照。

### 対象判定は「ピタゴラ」の部分一致

判定の対象は番組名（`tvSeriesName`）であり、サブタイトルは見ない。先頭一致では `大人のピタゴラスイッチ` を取りこぼすため、部分一致にする。部分一致であれば 3 シリーズすべてを 1 つの条件で拾える。

### 放送局を属性として持たない

取得対象は E テレと総合の 2 波だが、放送局は API 呼び出しの引数であって放送の属性ではない。放送日時が分かれば番組表で局を確認できるため、サマリにも表示しない。

### 放送データを永続化しない

NHK 番組表 API の規約が、情報提供期間を超えたデータの保持を禁止している。また週 1 サマリ方式では前回の通知内容を保持する必要がないため、永続化する動機もない。
