# 要件定義

前提: 目的・スコープ・やらないことは [concept.md](./concept.md)、用語・データモデルは [domain.md](./domain.md) を参照。

## 制約条件・前提条件

| ID | 制約 | 出典 |
|---|---|---|
| C-001 | 通知は LINE Messaging API のプッシュメッセージで送る。LINE Notify は 2025-03-31 に終了済みで使用できない | [LINE Notify 終了告知](https://developers.line.biz/en/news/2025/04/01/line-notify/) |
| C-002 | 月間の送信メッセージ数を 200 通以内に収める。無料プランの上限で、超過分は追加購入できず、その月は送信不可になる | [Messaging API の料金](https://developers.line.biz/ja/docs/messaging-api/pricing/) |
| C-003 | 通知用の LINE 公式アカウントを 1 つ開設し、Messaging API を有効化して使う。開設時にビジネスマネージャーとの接続が必要（ビジネスタイプは「個人事業主」。法人番号・サイト URL なしで作成できることを確認済み）。ボット専用アカウントを公式アカウントと別に作る経路は存在しない | [Messaging API を始めよう](https://developers.line.biz/ja/docs/messaging-api/getting-started/) / [接続必須化の告知](https://www.lycbiz.com/jp/news/line-official-account/20250617/) |
| C-004 | 認証には長期チャネルアクセストークン（無期限）を使い、GitHub Actions Secrets に保存する | [チャネルアクセストークン](https://developers.line.biz/ja/docs/basics/channel-access-token/) |
| C-005 | 番組表の取得には NHK 番組表 API Ver.3 を使う。API キーが必要（無料、1 アカウント 1 キー） | [NHK 番組表 API ポータル](https://api-portal.nhk.or.jp/) |
| C-006 | 取得可能な期間は当日から 7 日先まで（当日を含む 8 日分）。8 日先を指定すると 400 が返る。過去日は取得できない | 実レスポンスで確認（[nhk-api.md](./nhk-api.md)）。[サービス案内](https://api-portal.nhk.or.jp/service-guide) は「8 日先まで」と読めるが実際は 7 日先まで |
| C-007 | API の利用回数は 300 回/日。過去 24 時間のローリングで判定され、超過するとキーが一時的に無効になる | [FAQ](https://api-portal.nhk.or.jp/faq-page) |
| C-008 | 通知メッセージに「情報提供:ＮＨＫ」を表示する。NHK ロゴは使用しない | [利用規約 第10条](https://api-portal.nhk.or.jp/terms) |
| C-009 | 情報提供期間を超えた番組データを保持しない | [利用規約](https://api-portal.nhk.or.jp/terms) |
| C-010 | （欠番）GitHub Actions の `schedule` を使わなくなったため削除（C-012） | - |
| C-011 | （欠番）同上 | - |
| C-012 | 定期実行に GitHub Actions の `schedule` を使わない。指定時刻から約 4 時間遅れての起動が続けて発生しており、実行時刻を制御できない。外部の cron サービス [cron-job.org](https://cron-job.org/) から GitHub REST API でワークフローの `workflow_dispatch` を呼び出す | 実測（2026-09-27・2026-10-04 の schedule 実行がいずれも約 4 時間遅延）。[ワークフローの手動実行 API](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event) |
| C-013 | 実行時刻は JST 05:30〜23:59 の範囲に置く。JST 0 時〜5 時台に実行すると、取得範囲の最終日（当日 + 7 日）に対して API が 400 を返す。API 側の「当日」が放送日の区切り（05:00 / 05:30）で切り替わるためと推定している | 実測（JST 00:58・01:07 の実行で最終日のみ 400）。区切りの推定は [nhk-api.md](./nhk-api.md)「`date` の範囲は 24 時間ではない」 |

## 機能要件

### 機能一覧

| 機能ID | 機能名 | 機能概要 | 優先度 | 備考 |
|---|---|---|---|---|
| F-001 | 番組表の取得 | 対象期間 8 日分の番組表を NHK 番組表 API から取得する | Must | E テレ・総合の 2 波が対象 |
| F-002 | 対象放送の抽出 | 取得結果から、番組名に「ピタゴラ」を含む放送を抽出する | Must | 特別版かどうかの判定はしない |
| F-003 | サマリの生成 | 抽出した放送を 1 通のメッセージに整形する。各放送について放送日時・番組名・サブタイトルを含める。末尾に「情報提供:ＮＨＫ」を付ける | Must | C-008 を満たす |
| F-004 | LINE への送信 | 生成したサマリを自分宛にプッシュ送信する | Must | 1 回の通知を 1 リクエストで送る |
| F-005 | 週次実行 | 日曜夜に F-001 〜 F-004 を自動実行する | Must | cron-job.org から `workflow_dispatch` を呼び出す（C-012）。実行時刻は C-013 の範囲内 |

全 5 機能が Must であり MoSCoW の目安（6 割）を超えるが、これは優先順位をつけていないためではなく、機能を最小構成まで削った結果である。どれが欠けても通知が成立しない。

## 非機能要件

| カテゴリ | 要件 |
|---|---|
| 可用性 | 可用性目標を設けない。週 1 実行であり、失敗しても翌週の実行で復帰する。cron-job.org 側の遅延・停止を許容する |
| 性能 | 実行時間に要件を設けない。API 呼び出しは 1 回の実行あたり 16 リクエスト以内（2 波 × 8 日）に収める |
| 拡張性 | 通知先の差し替えは想定しない。対象番組名（「ピタゴラ」）は設定値として外出しし、コード変更なしで変更できるようにする |
| 運用保守 | 実行に失敗した場合はワークフローを失敗させ、GitHub からの失敗通知メールで検知する。`workflow_dispatch` の呼び出し自体の失敗（トークン失効など）はワークフローが起動せず GitHub から通知されないため、cron-job.org の失敗通知で検知する。監視の仕組みは作らない。ログは GitHub Actions のログのみとする |
| 移行性 | データを永続化しないため、移行の対象がない |
| セキュリティ | 認証情報（LINE チャネルアクセストークン、LINE user ID、NHK API キー）は GitHub Actions Secrets に保存し、リポジトリに含めない。cron-job.org には `workflow_dispatch` の呼び出しに必要な権限だけを持つ GitHub トークン（対象リポジトリ限定・Actions の書き込み権限のみ）を登録する。リポジトリは private とする。扱う個人情報は自分自身の LINE user ID のみ |

### 明文化する前提

書かなければ「やらなくてよい」と解釈されるため、以下を要件として明記する。

- 通知メッセージは日本語で記述する
- 日時は日本標準時（JST）で表示する
- 1 回の通知は 1 リクエストにまとめる。C-002 の通数は送信リクエスト数でカウントされるため、分割すると通数が増える
- 対象放送が 0 件の場合も特別扱いせず、通常どおり送信する。0 件専用の分岐は設けない
